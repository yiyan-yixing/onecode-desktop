# 产品审视与优化计划 · OneCode Desktop

> **类型:** 产品优化 | **视角:** 苹果式产品经理审视 | **状态:** 🟢 P0 已完成（v0.3），P1/P2 待排期
> **建立日期:** 2026-07-23
> **来源:** 以"苹果最顶尖产品经理"视角对当前展品的一次完整诊断

---

## 一句话诊断

**工程扎实、体验割裂。** Rust/PTY/RingBuffer/健康检测的地基打得很好，但产品还停留在"多开终端的工具"，没有讲清楚"为什么是它"；且视觉语言、信息架构、首次体验三处自相矛盾，作为展品第一眼就露怯。

---

## 一、定位层问题（最致命，先于一切）

| # | 问题 | 说明 |
|---|------|------|
| L1 | **价值主张不锐利** | 定位从 "Claude Code shell" 摇摆到 "multi-kernel AI terminal manager"。但"管理多个 AI 终端"是品类描述，不是购买理由——iTerm2 多 tab + Claude Code 就能做。必须回答："OneCode 让你的一人公司同时跑 N 个 AI 员工，各司其职、永不掉线。" 现在 README 第一句讲的是 *what*，不是 *why*。 |
| L2 | **名实不符** | "OneCode"（代码）+ 暖色 Cowork 主题，但本质是终端复用器。名字暗示"写代码"，实际是"调度 AI"。认知错位。 |
| L3 | **目标用户模糊** | 一人公司开发者？所有 AI coding 用户？空状态写英文 "AI-native development environment"，状态栏又混中文"连接断开""点选"——连语言受众都没定。 |

## 二、体验层问题（展品现场肉眼可见）

| # | 问题 | 代码位置 |
|---|------|----------|
| E1 | **空状态冷漠** | 截图就是空状态：`{ }` orb + "OneCode" + "AI-native development environment" + "⌘K to begin"。苹果式空状态要有温度、有引导、有下一步——这里只甩一个快捷键。`src/index.html` `.term-empty` / `src/main.js` emptyOrb 点击逻辑 |
| E2 | **视觉语言分裂** | 左侧暖色（cream/linen）+ 中间深色（void/abyss）+ 右侧又暖色，三者硬拼无过渡。`src/theme.js` 注释写 "dark-only Aurora paradigm"，可侧栏明明是亮暖色——主题系统自相矛盾。`src/styles.css` `:root` 色板 |
| E3 | **信息架构过载** | 同时存在：左 orbital（项目/探索双 tab）+ 右面板（file/agents 双 tab）+ 终端 + 状态栏徽章 + ⌘K 面板 + @mention + wizard。三个"侧边面板"概念并存；左侧"探索"与右侧"agents"功能重叠。`src/orbital.js` / `src/file-explorer.js` / `src/agents-list.js` |
| E4 | **文案中英混杂** | "Ready" / "to begin" / "Sidebar" vs "连接断开" / "点选"。一个产品两套语言人格。`src/index.html` 状态栏、`src/main.js` disconnect banner |
| E5 | **快捷键暴力堆砌** | 状态栏直接平铺 `⌘B / ⇧⌘T / ⌘W / ⌘1-9`。苹果用菜单栏 + 帮助提示做发现性，底栏只留状态。`src/index.html` `.statusbar` |
| E6 | **设置藏得太深** | Preferences 藏在 ⌘K 输入 `>` 里，非独立窗口/面板。改 API Key、默认后端这种高频操作路径过长。`src/palette.js` `_renderSettings` |
| E7 | **双重首次路径** | wizard（全屏检测环境+配 API）与空状态 ⌘K 是两套首次体验，无接续关系。`src/wizard.js` / `src/index.html` `.term-empty` |

## 三、功能层问题（距离理想形态的缺口）

| # | 问题 | 代码位置 |
|---|------|----------|
| F1 | **跨平台是空头支票** | `tauri.conf.json` 配了 dmg/appimage/deb/msi/nsis，README 却写"仅支持 macOS Apple Silicon"。Linux/Windows 打不出去。`src-tauri/tauri.conf.json` `bundle.targets` |
| F2 | **终端内容非资产** | AI 对话是核心资产，但 SessionStore 只存配置不存内容。崩溃/重启后历史丢失；RingBuffer 有 replay 不落盘；无跨终端搜索、标记、导出。`src-tauri/src/session/` / `src-tauri/src/pty/slot.rs` RingBuffer |
| F3 | **健康检测只告警不自愈** | 检测到僵尸/RSS 异常只弹状态栏告警，不自动重启/隔离——"永不掉线"承诺没兑现。`src-tauri/src/pty/health.rs` |
| F4 | **agents/会话只读** | 读 `~/.claude` 镜像展示，但不能在 OneCode 内创建/编辑 agent。`src-tauri/src/cc_status.rs` / `src/agents-list.js` |
| F5 | **无长任务通知** | 量化回测、模型训练跑完无系统通知——一人公司"夜间 AI 自治"场景刚需。`src-tauri/src/tray.rs`（仅有托盘，无通知） |
| F6 | **无自动更新** | Release workflow 有签名+公证占位，但 Tauri updater 未启用。`.github/workflows/` / `tauri.conf.json` |
| F7 | **无多窗口/分屏** | 单窗口固定 1200×800，无法并排看两个终端、无法按业务线（quant/content/ecom）开独立工作区。`tauri.conf.json` `windows` |
| F8 | **安全债** | CSP 残留 `'unsafe-eval' 'unsafe-inline'`。`tauri.conf.json` `security.csp` |

## 五、给展品的一句话建议

> 现在的 OneCode 是一个"功能齐全但说不清自己是谁"的工具。展示前只需做 P0 五件事——尤其统一视觉语言、重写空状态、定稿定位文案——就能从"开源 demo"质感跃迁到"苹果级产品"质感；P1 做完，"永不掉线的 AI 员工调度台"这个承诺才真正成立。

## 推进方式

- 本计划为总纲，具体执行时每个 P0/P1/P2 编号拆为独立任务，迁入 `roadmap.md` 对应版本里程碑（建议新增 v0.3 = P0、v0.4 = P1、v1.0 = P2）。
- 任务完成后在此表更新状态标记（🔴 → 🟡 → 🟢），并在 `CHANGELOG.md` 记录。
