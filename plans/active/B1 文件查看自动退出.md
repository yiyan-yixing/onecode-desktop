# B1: 文件查看时等待一会就会自动退出

> **类型:** Bug | **严重度:** 高 | **优先级:** P0 | **状态:** 🟢 修复中（代码已改，待验证）
> **目标完成:** 2026-07-08 (二)

## 问题描述

打开文件查看（右侧面板预览），闲置等待一段时间后窗口自动关闭。
需确认具体退出模式：整个窗口关闭 / 面板折叠 / 预览面板关闭。

## 代码定位

- **JS 侧:** `src/file-explorer.js` — `FileExplorerController`
  - `openFile()` → `ipc.fsReadFile(path)` → `_renderPreview()`
  - `closePreview()` — 唯一关闭入口（用户按 Esc / 点 X / 导航目录时调用）
  - `setVisible()` — 15s 自动刷新定时器
- **Rust 侧:** `src-tauri/src/pty/health.rs` — 每 5s 健康检测
  - `HealthAction::Stale` — 进程不在但 slot 认为运行中
  - `HealthAction::Kill` — 僵尸进程
- **IPC:** `src/ipc-bridge.js` — `safeInvoke()` 连续 3 次失败触发 `ipc-disconnected`
- **面板折叠:** `src/main.js` line 151-162 — 右面板 toggle 逻辑

## 根因分析（已定位）

### PRIMARY: 15s 自动刷新 → navigate() → closePreview()

调用链：

1. `setVisible(true)` 启动 15s 定时器（`file-explorer.js` line 511-515）
2. 定时器调用 `refresh()` → `navigate(this._currentPath)`（line 270-273）
3. `navigate()` **无条件调用** `this.closePreview()`（line 246-247）

**结果：** 用户打开文件预览后最多 15s，预览就被自动关闭。这与 bug 报告完全吻合。

### SECONDARY: Tab 切换触发 syncCwd → navigate → closePreview

- `main.js` line 95-98: `tabManager.onChange` 回调调用 `fileExplorer.syncCwd()`
- `file-explorer.js` line 277-283: `syncCwd()` 在 cwd 变化时调用 `navigate()` → `closePreview()`
- PTY 退出/重启事件也触发 `onChange`，导致预览意外关闭

### 非 Root Cause

- PTY health loop（`health.rs`）：仅 emit 告警事件，不自动 kill 或关闭
- Tauri Channel 超时：Channel silent failure 不直接关闭面板
- session 模块：无超时清理逻辑
- 无 WebSocket / heartbeat 机制

## 修复方案（已实施）

### B1-4: navigate() 不再无条件调用 closePreview()

**修改文件:** `src/file-explorer.js`

**改动 1 — `navigate(path, opts)`:**
- 新增第二个参数 `{ skipClosePreview: false }`
- 当 `opts.skipClosePreview === true` 时，跳过 `closePreview()`
- 默认行为不变：用户点击目录导航时仍会关闭预览

**改动 2 — `refresh()`:**
- 调用改为 `this.navigate(this._currentPath, { skipClosePreview: true })`
- 15s 自动刷新不再杀死预览面板

**改动 3 — `setVisible()` 注释更新:**
- 添加 B1-4 注释说明 refresh() 已传 skipClosePreview:true

### B1-5: syncCwd() 路径增加路径未变判断

**已确认:** 代码中 `syncCwd()` 已有守卫 `if (!this._currentPath || this._currentPath !== cwd)`，
路径未变时不会调用 navigate()。无需额外修改。
