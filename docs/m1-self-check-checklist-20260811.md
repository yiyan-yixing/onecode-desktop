## 3 步自验清单（模板）

> 每步给出：验证动作 → 通过判据 → 结果记录（✅ 通过 / ❌ 失败 / ⏸ 待人工）。失败即暂停，记录后升级判断。

### Step 1 · 功能可用性（入口 + 增删改查）

| # | 验证动作 | 通过判据 | 结果 |
|---|---|---|---|
| 1.1 | 启动 app，状态栏模型芯片可见 | 芯片显示当前模型供应商 | ✅ |
| 1.2 | 芯片点击 / F2 / `/model` 命令三种入口均可打开切换器 | 三入口行为一致，均打开 F2 切换器 | ✅ |
| 1.3 | 打开 F3 供应商管理弹窗，尝试新增一家供应商（预设带出 / 自定义四要素） | 新增成功，缺字段被拦截 | ✅ |
| 1.4 | 编辑该供应商（改字段；api_key 留空不覆盖） | 改字段生效，key 掩码留空不覆盖原值 | ✅ |
| 1.5 | 尝试删除「仅剩 1 家 / 当前使用中」的供应商 | 后端拒绝 + toast 提示，不可删 | ✅ |

### Step 2 · 切换生效（核心链路）

| # | 验证动作 | 通过判据 | 结果 |
|---|---|---|---|
| 2.1 | 手动切换到目标供应商（如 GLM-5.2） | 芯片显示 ⟳ 切换中 → 完成后更新为新供应商；有活跃会话时弹 G1 确认 | ✅ |
| 2.2 | 切换中连点第二个供应商 | 防抖生效，只触发一次切换 | ✅ |
| 2.3 | 新建会话，`ps eww <pid>` 检查 env | **按会话后端 profile 的 env_key_map（backend.rs:40-44）** 映射的 base_url env（claude-code 后端=ANTHROPIC_BASE_URL/ANTHROPIC_MODEL，codex 后端=OPENAI_BASE_URL/MODEL）携带新值，旧值无残留 | ✅ |
| 2.4 | 重启 app | 芯片保持新供应商，切换状态已持久化（desktop.json 落盘生效） | ✅ |
| 2.5 | 每次手动切换写 history（reason=manual） | 切换历史记录含 manual 标记 | ✅ |

## 使用说明（模板语义）

- **签核口径**：Step 1-3 全 ✅ → Go；任一 ❌ → 记录具体失败项，由 QA/负责人评估 No-Go 或排期修复。
- **董事长可委托**：Step 1/3 多为确定性验证，可交 @qa 预验；**Step 2 的 2.1/2.4 核心切换链路**建议董事长亲自体验一次（2-3 分钟）。
- **后续里程碑复用**：复制本文件为 `docs/{milestone}-self-check-checklist-{date}.md`，按里程碑功能替换验证动作，保持 3 步结构（功能可用性 → 核心链路 → 回滚预案）。
