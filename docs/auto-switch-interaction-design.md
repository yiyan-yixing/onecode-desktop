# onecode-desktop 模型自动切换 — 产品交互设计

> 状态：**v0.1 draft** · 日期：2026-08-08 · 配套：`auto-switch-design.md`（技术方案）
> 目标：让用户在 onecode-desktop 内**一键切模型/供应商**，并让系统在**供应商故障时自动切到备用**。交互层对「重启式 failover / 代理式无缝 failover」不感知（UX 相同，仅「是否无缝」不同）。

---

## 1. 设计目标与原则
1. **当前用哪个模型，永远一眼可见**——状态栏常驻「模型芯片」，单一真相。
2. **切换比配钥匙快**——手动切换 ≤2 次点击；自动切换零操作、只通知。
3. **失败是常态**——failover 默认开启、静默执行、但**必须可见可查**（toast + 历史）。
4. **首次引导，预设做选项**——第一次启动直接展示配置引导（讲清供应商/Base URL/API Key/型号四要素），预设（DeepSeek-V4-Flash / GLM-5.2）退居为下拉选项「少打字」用，不替代引导，防盲配。
5. **不打断即最大尊重**——切换可能重启会话，必须在做之前明确告知（尤其有活跃任务时）。

---

## 2. 心智模型（一句话）
> 「模型 = 一家供应商 + 一个型号；你可以随时换供应商，系统会在供应商出问题时自动换到你的备用。」

映射：
- 供应商（Provider）= 一家服务商（如 DeepSeek / GLM / 自定义网关）
- 型号（Model）= 具体模型（DeepSeek-V4-Flash / GLM-5.2）
- 备用顺序（Failover queue）= 出问题时的撤退路线（P1 → P2 → …）

## 2.5 外观与操作体验：VS Code 设计语言（董事长 2026-08-08 拍板 A+B）

> 原则：**VS Code 是「皮肤」，多终端并行编排的「AI 员工调度台」是「内核」**——借 VS Code 的体验拉平用户预期，但不丢差异化。

### A · 借外观（独立 app 内拉齐 VS Code 体验）
- **编辑内核 = Monaco**：引入 VS Code 同款开源编辑器，替换/增强现有文件预览 → 获得语法高亮/多光标/查找替换等 VS Code 级编辑能力。
- **视觉 = VS Code 色板/主题/codicon**：dark/light token 化；现有 titlebar/侧栏/状态栏布局已近 VS Code，对齐成本低。
- **操作范式**：Quick Open（⌘P）、多标签页、活动栏，对齐 VS Code 心智；命令面板（⌘K）沿用。
- **不丢差异化**：核心仍是「一个窗口跑 N 个 AI 员工」的多终端并行编排。

### B · 轻桥接（与 VS Code 双向，不重写）
现状已有「用 VS Code 打开当前目录」按钮 → 升级为**双向通道**：
1. **编辑双向**：桌面改文件 ↔ VS Code 打开同一文件/项目。
2. **配置同步**：模型/供应商（auto-switch 的 provider 配置）与 VS Code 侧共享，切模型两端同步。
3. **deep link**：任务/会话/终端可转发到 VS Code（反之亦可）。
- 原则：桥 = 顺手通道，**不做双产品线**（不因桥接而维护两套核心）。

### 对 auto-switch 交互的影响
- 模型芯片（F2）、供应商管理（F3）、failover 设置（F4）落位**不变**（状态栏/命令面板/设置面板），视觉按 VS Code token 实现。
- Monaco 补上「app 内编辑文件」能力，与 xterm 终端并置——正好补当前「文件预览」短板。

## 3. 信息架构（新增/改动位置）
```
onecode-desktop
├── 状态栏  ← 新增【模型芯片】常驻（当前供应商+型号，点击即切换入口）
├── 命令面板(palette)  ← 新增 "/model" 命令（同 Claude Code 心智）
├── 设置面板
│   └── 「模型供应商」  ← 新增页：供应商列表 + 管理 + 自动切换开关
└── 会话/终端视图  ← 切换生效时这里的会话会重启（需明确告知）
```
> 状态栏已有 cc-status 区域，模型芯片与其并列。不新建独立工具栏。

## 4. 用户流程（含线框）

### F1 · 首次配置（引导式，不预设）
时机：`wizard_completed=false` 或未配置 api_key 时。**首次不预设任何供应商**，直接展示配置引导内容 + 配置表单。
```
┌─ 首次使用 · 配置你的模型 ─────────────────────────────┐
│                                                      │
│ 📖 先读一下（配置引导）                                  │
│  · 模型 = 一家「供应商」+ 一个「型号」                    │
│  · 供应商：提供 AI 接口的服务商                          │
│    （如 DeepSeek、GLM，或你自己/公司搭建的网关）          │
│  · Base URL：供应商的接口地址（HTTP 开头）               │
│  · API Key：去供应商后台申请的一串密钥（保密）            │
│  · 型号：该供应商下的具体模型名（如 deepseek-v4-flash）   │
│  ❓ 看不懂？ [查看完整指南] [示例截图]                     │
│                                                      │
│ 开始配置：                                             │
│  供应商    [ 选择或手动填写 ▼ ]    ← 预设可在此选，非默认    │
│  Base URL [______________________]                    │
│  API Key  [______________________]  👁                 │
│  型号      [______________________]                    │
│                                                      │
│  [ 测试连接 ]      [ 完成配置 ]                          │
│                                                      │
│  ───────────  或  ───────────                         │
│  [ 稍后配置 ]（先逛产品，之后从状态栏芯片随时可配）          │
└──────────────────────────────────────────────────────┘
```
- **引导在前，预设只是下拉里的一项**——首次用户先理解「供应商/Base URL/API Key/型号」四要素再填，不是点个预设就开跑。
- 「供应商」下拉内含两档预设（DeepSeek-V4-Flash / GLM-5.2），选中自动带出默认 Base URL 与型号，用户只需补 API Key——**预设退居为「少打字」手段，不是引导的替代**。
- 「测试连接」复用 F3 的连通性测试，通过才允许「完成配置」；失败显示具体原因（网络/Key/型号名）。
- 点「完成配置」→ 写 `desktop.json` → 启动会话；点「稍后配置」→ 状态栏芯片显示引导色 `[ 配置模型 ▼ ]`，随时可回来。

### F2 · 手动切换（≤2 步）
入口 A：状态栏芯片（推荐）
```
┌───────────────────────────────────────────────────────────┐
│ [◦] onecode   ~/my-project   ──  ──  ──   [ GLM-5.2 ▼ ]    │
└───────────────────────────────────────────────────────────┘
                      点击芯片 ↓
┌─ 选择模型 ───────────────────────────┐
│ 🔍 搜索                                   │
│ ────────────────────────────────      │
│ ● GLM-5.2                  ← 当前      │
│ ● DeepSeek-V4-Flash   (推荐·快)        │
│ ────────────────────────────────      │
│ ▸ 管理供应商 …                          │
└───────────────────────────────────────┘
```
- 选择非当前项 → 若有活跃任务，出确认（见 G1）；无任务直接切。
- 入口 B：命令面板输入 `/model`，行为同上。

切换确认（**仅在会重启会话时**）：
```
┌─ 切换模型 ───────────────────────┐
│ 将切到 DeepSeek-V4-Flash        │
│ 当前有 2 个活跃会话，切换会重启它们│
│                    [取消] [切换]  │
└──────────────────────────────────┘
```

### F3 · 供应商管理
入口：设置 → 模型供应商。
```
┌─ 模型供应商 ───────────────────────────────────────────────┐
│ [+ 新增]  [管理备用]   状态图例: ●使用中 ●可用 ●失败          │
│ ┌──────────────┬────────────┬────────┬────────┬──────────┐ │
│ │ 供应商/型号    │ 状态        │ 延迟    │ 上次结果│ 操作     │ │
│ ├──────────────┼────────────┼────────┼────────┼──────────┤ │
│ │ GLM-5.2      │ ● 使用中    │ 180ms  │ 正常   │ [编辑][×] │ │
│ │ DeepSeek-V4-Flash│ ● 可用  │ 90ms   │ 正常   │ [编辑][×] │ │
│ └──────────────┴────────────┴────────┴────────┴──────────┘ │
│ 自动切换  [ ● 开 ]  备用顺序见「管理备用」                      │
└────────────────────────────────────────────────────────────┘
```
- 「新增」→ 预设列表（DeepSeek-V4-Flash / GLM-5.2 / 其他）或自定义表单（名称/base_url/api_key/型号）。
- 每行带「测试」：发一条最小 completion，返回延迟 + 状态。
- 删除使用中的供应商 → 先要求切换/确认（不可删除当前唯一）。

### F4 · 自动切换设置（备用顺序 + 判定）
入口：设置 → 模型供应商 → 「管理备用」。
```
┌─ 自动切换 · 备用顺序 ──────────────────────────────┐
│ 自动切换           [ ● 开 ]                        │
│ 说明: 当前供应商连续失败 N 次后，自动换到下一个备用      │
│ ──────────────────────────────────────────────  │
│ 撤退路线（从上到下）:                               │
│   1. GLM-5.2          [ 当前 ]  [↑][↓][✕]         │
│   2. DeepSeek-V4-Flash           [↑][↓][✕]        │
│   [+ 添加备用]                                    │
│ ──────────────────────────────────────────────  │
│ 失败判定:                                         │
│   连续失败   [ 4 ] 次触发                          │
│   单次超时   [ 60 ] s                             │
│ 切换方式: ( ) 重启会话  (●) 无缝转发(需代理)        │
│                                                 │
│         [ 保存 ]                                  │
└─────────────────────────────────────────────────┘
```
- 队列首项=当前；用户可拖拽/上下调序。
- 「切换方式」底层差异：无代理=重启式，有代理=请求级无缝。**交互层不感知，只读文案**。

### F5 · 自动切换发生时的反馈
```
触发瞬间（系统托盘级 toast，非模态、不抢焦点）:
┌──────────────────────────────────────────────┐
│ ⚠ GLM-5.2 连续失败 4 次                        │
│ → 已自动切到 DeepSeek-V4-Flash               │
│    [查看详情]             [关闭]              │
└──────────────────────────────────────────────┘
状态栏芯片同步更新为 DeepSeek-V4-Flash（短暂高亮闪烁）。
```
- 无缝转发时：当前对话不中断，用户可能只看到 toast。
- 重启式时：正在进行的任务会中断 → toast 文案变为「已切到 DeepSeek-V4-Flash，当前会话已重启」。
- 「查看详情」→ 切换历史（时间 / 从→到 / 原因[连续失败/超时/限流/手动]）。

### F6 · 状态常驻可见性
hover 状态栏芯片：
```
┌─ 当前模型 ────────────────────┐
│ 供应商   GLM (oneapi 网关)      │
│ 型号     GLM-5.2              │
│ 健康     ● 正常 · 180ms        │
│ 备用     DeepSeek-V4-Flash    │
│ 最近切换  08-08 14:32（失败切） │
│ [进入设置]                     │
└───────────────────────────────┘
```

## 5. 状态与反馈规范
| 状态 | 芯片表现 | 附加 |
|---|---|---|
| 正常 | `[ GLM-5.2 ▼ ]` 常显 | — |
| 切换中 | `[ ⟳ GLM-5.2 ▼ ]` 旋转 | 防重复点击（去重） |
| failover 后 | 新模型 + 短暂高亮 | toast + 历史记录 |
| 全部备用也失败 | `[ ⚠ 无可用模型 ▼ ]` 红点 | 立即模态提示 + 引导检查 Key/网络 |
| 未配置 | `[ 配置模型 ▼ ]` 引导色 | 点击进 F1 向导 |

## 6. 边界与异常
1. **用户主动取消的请求不触发 failover**（只统计 API/网络错误，不统计 cancel）。
2. **切换中防抖**：同一 `供应商:模型` 的切换进行中时，重复触发跳过（cc-switch 的 pending_switches 语义）。
3. **当前供应商被删/失效** → 自动退到队列首备用，若队列空则进「无可用模型」态。
4. **无缝/重启差异只在事件文案上暴露**，不改变用户操作路径。
5. **Key 失效（401）**视为高置信失败，可调低阈值；限流（429）按独立规则记录。
6. **「备用顺序空 + 自动切换开」**：开自动切换时若队列空，自动把当前设为 P1（避免死锁）。
