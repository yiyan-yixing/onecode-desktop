> 这份是**交账**用的：目标五项各做到什么程度、证据在哪、还差什么、哪些是"未实测"或"已被我自己推翻的"。
> 工程细节与逐刀记录在 [`2026-10-14-console-product-spec.md`](./2026-10-14-console-product-spec.md)（§10，二十六刀）；

## 一句话结论

**目标五项都有可运行、可验证的落地实现；不存在"只剩设计没写代码"的项。**
剩下的都是**增强**（项目级引擎定义、ACP 常驻槽位）与**证据边界**（窗口视觉层、与真实 ACP agent 的互通）。

**产品一句话**：`eng/onecode-desktop` = 一个**可换引擎**的指挥台。
一个人当董事长，手下是一批 **Slot**（终端槽位 / 结构化槽位），
每个 Slot 有**身份**（员工）、**能力**（技能）、**权限姿态**、**模型路线**；
产出要**证据化验收**，工作有**任务板 + 审查队列 + 真实金额的账本**。

## 一、目标逐项交账

### ① 整合各家终端 → 一个可换引擎的调度台

| 要素 | 状态 | 证据 |
|---|---|---|
| 统一驱动多种引擎 | ✅ | 内置 7 档（claude-code / codex / opencode / crush / …），`list_backends` 真机返回 7 |
| 引擎可扩展（用户自定义） | ✅ | 全局 `~/.onecode/engines.json` + **项目级**（只能新增）；加 / 覆盖 / `base` 继承；无配置时内置 7 档逐字段不变 |
| 能力协商（不猜） | ✅ | 探测引擎自己的 init 事件（539ms 拿到模型/权限档/凭据来源/工具集），**探测在推理前 kill → 不花 token** |
| **终端槽位**（经典终端 + TUI 类） | ✅ | xterm + PTY，身份/姿态/技能/路由注入，诚实降级提示（身份未注入 / 已从 X 切走 …） |
| **结构化槽位**（不走 TUI） | ✅ | `structured_slot`：消息列表 + 多轮 + 每轮结算 |
| **多轮上下文** | ✅ | 实测引擎 `--session-id` **不接续** → 改为**本机回放**（引擎无关，实测答出早期事实） |
| **ACP 类**（目标点名的） | ✅ | 按 [v1 规范](https://agentclientprotocol.com/protocol/v1/overview)实现；对 mock 做协议一致性；**真机端到端 18/18** |
| ACP 常驻槽位 | ❌ | 目前是"结构化槽位的一轮一次"，不是长连接常驻 |
| **项目级 `engines.json`** | ✅ | `<项目>/.onecode/engines.json`，**只能新增不能覆盖**（克隆仓库改不掉要跑的命令）；真机 `list_backends` 8 个引擎 |

### ② 按员工 / 任务自选模型（含本地模型档）

| 要素 | 状态 | 证据 |
|---|---|---|
| 每槽 provider+model 落到 env | ✅ | 凭据/BaseURL/模型注入 + 清陈旧 env |
| 按**员工**自选 | ✅ | 花名册绑定与实际路线并排显示 |
| 按**任务**自选 | ✅ | 任务字段 → 视为"显式指定" → **压过员工花名册**（跨模块端到端测试） |
| 本地模型档 | ✅ | localhost/127.0.0.1 等**不要求凭据**，不会被误切走 |
| failover（撤退队列 + 历史） | ✅ | 静态不可用触发；历史 FIFO |
| **熔断（连败阈值）** | ✅ | **真机实测触发**：不可达供应商 + 阈值 1 → 切档，历史记 `consecutive_failure`（花费 **$0**） |
| 自动切换在界面可见 | ✅ | warn 样式 +"连续失败，已自动切换…（终端已重启）" |
| 用引擎自报 `contextWindow` 替换型号表 | ❌ | 引擎已自报窗口，但推导路径仍用内置表 |

### ③ 管理员工（花名册 + 能力组合 + 权限姿态 + 模型）

| 要素 | 状态 | 证据 |
|---|---|---|
| Slot 花名册 + 员工身份 | ✅ | 4 处 agent 目录解析；身份注入终端 |
| 能力组合（技能） | ✅ | 5 个技能根；渐进披露；127KB 技能走 deferred 给路径；找不到的**如实列出** |
| 权限姿态 | ✅ | 档位映射经真机校验（`plan` 合法、`planMode` 会让 CLI 秒退）；`apply` 先整段移除再写，幂等 |
| 模型 | ✅ | 员工级 + 任务级 |
| **默认不提权** | ✅ | 空 / 拼错的权限字段都**不提权**；继承档**一个参数都不加**（5 条不变量测试钉住） |

### ④ 管理产出（交付物 + 证据化验收）

| 要素 | 状态 | 证据 |
|---|---|---|
| 交付物 = 真文件 + 证据 + 状态 | ✅ | 声明文件 `exists` 真核对、字节数、问题如实标出 |
| 证据分级 | ✅ | 可机器验证 / 实测 / 不可验证 / **不是证据**（模型自述归最后一类） |
| 证据**真的跑** | ✅ | 真仓库 numstat `+1`；退出码/输出/非零码如实记录；超时墙钟有界 |
| 只有人能验收 | ✅ | 验收命令**不暴露给模型** —— 模型无法把自己的产出标记为已验收 |
| 批量操作 / 归档进知识库 | ❌ | 未做 |

### ⑤ 管理工作（任务板 + 调度 + 账本 + 审查队列）

| 要素 | 状态 | 证据 |
|---|---|---|
| 任务板 | ✅ | 任务 = **声明**（`<id>.json`）+ **人的裁决**（`<id>.human.json`）两份文件（真机产物可见） |
| 状态语义 | ✅ | agent 自报的 `done` 只算自报、**不生效**；人的裁决压过声明（真机自检断言） |
| 调度（派活） | ✅ | 真机实测：PTY 收到任务正文、**不代按回车**、提示写 `review` 等验收 |

## 二、验证层（都能自己复跑）

| 层 | 命令 | 当前 | 说明 |
|---|---|---|---|
| Rust 单元 | `make test` | **285 passed / 0 failed** | 并行 ×2 + 串行一致 |
| JS 单元 | `npm test` | **331 passed / 0 failed** | 17 个测试文件 |
| 前端渲染 | `npm run test:render` | **7/7** | 真实 CSS 结构下渲染（Chrome headless） |
| 前端启动 + 真实流程 | `npm run test:boot` | **30/30** | 真实 `index.html`+`main.js`，`__TAURI__` 打桩；含派发/工作台/派活/结构化槽位 |
| **真机自检**（基线） | `ONECODE_SELFCHECK=1` 起 app | **19/19（跳过 1）** | 真实 WebView 对真实命令：任务板读写往返、账本、结构化槽位形状、启动降级 |
| **真机自检**（+ ACP 引擎） | 同上 + 临时 HOME 注册 ACP 引擎 | **18/18** | 含 3 条 ACP 断言（回复 / stopReason / 协议标签） |
| 真机整机 | `make build` + 起二进制 | 0 panic | 前端→Rust IPC 通；`[startup]` 降级带后果被记录 |

三条"危险检查"都有**反向对照**（证明它们真的会失败）：

| 检查 | 反向对照 |
|---|---|
| `test:boot` | 删掉"身份未注入"提示 → `FAIL`；派活偷偷加 `\r` → `FAIL`；坏 import → `MODULE_LOADED: no` |
| 真机自检 | 不显示启动降级 → `FAIL STARTUP_ISSUE_SHOWN` |
| 熔断 | 不可达供应商 → 真的切档（不是只跑单测） |

> 两次真机自检条数不同是**正常的**：ACP 那 3 条只在"当前引擎确实宣告 `protocol: acp`"时才跑，
> 否则显式跳过（**跳过 ≠ 通过**）。同理，花钱的 `structured_print_turn` 默认也是跳过。

**验证纪律**（二十六刀里形成的）：

1. **降级必须如实显示**，不能只躺在日志里（第 17 刀就是跑真机才发现）。
2. **桩会替你把漏掉的字段补上** —— 所以关键形状要钉在单元层 + 真机自检（第 21 刀）。
3. **跳过 ≠ 通过**：写不了的地方标 `SKIP` 并说明原因，不计入通过率。
4. **花钱的探测必须显式打开**（`ONECODE_SELFCHECK_NETWORK=1`）—— 自检不替用户花钱。
5. **观察失败与产品失败要分开**：只在"没观察到"时重试，一旦观察到 FAIL 立刻判失败。

## 三、★ 诚实清单

### A. 我标了"未实测"、后来**被自己推翻**的（2 例）

| 标的 | 当时的依据 | 实测结果 |
|---|---|---|
| `--permission-mode planMode` | bundle 里的形状 | **非法值**，会让终端秒退 → 改为 `plan`（第 11 刀） |
| `--session-id` 接续上下文 | bundle 里的形状 | **不接续**（第二轮输入从 10038 掉到 367 且模型说"没有之前的记录"）→ 改为本机回放（第 21 刀） |

**"标了未验证"不是免责，是待办。** 这两例都是"从 bundle 看到的形状"被当成了"实际行为"。

### A2. 真机验证抓到的**已修**缺口（累计 6 例）

| 缺口 | 怎么发现的 | 后果 |
|---|---|---|
| 启动降级只躺在日志里 | 真机启动（第 19 刀） | 用户看到"终端不见了"却不知原因 |
| 2 个注册了却没人能调的引擎命令 | 真机自检（第 20 刀） | 死表面 |
| `structured_send` 返回类型漏了视图 | 改命令时（第 21 刀） | 真前端显示"合计 $0" |
| 熔断抓不到连通性故障 | 真机触发熔断（第 26 刀） | 最该抓的故障抓不到 |
| 失败运行没被记账 | 同上 | "跑三次都失败"看起来像"什么都没发生" |
| **点名引擎不存在 → 静默跑别的** | 真机验证项目层（第 27 刀） | 你要 X 跑的是 Y，还没提示 |

### B. 至今**未实测**的

| 项 | 为什么没测 |
|---|---|
| 窗口**视觉**层（长得对不对） | 本沙箱**无屏幕录制权限**（`screencapture` 报 `could not create image from display`）。真机跑通、IPC 通、命令形状对，但"好不好看"只有浏览器级证据 |
| 与**真实** ACP agent 的互通 | 本机没有（`claude-agent-acp` / `codex-acp` 都不存在，第 11 刀已取证）。现有证据是"我们符合 v1 规范" |
| 有人真的拿它干一天活 | 需要你上手 |

### C. 已知缺口（我自己标出来的，不是不知道）

- ① 项目级 `engines.json`；ACP **常驻**槽位
- ② 窗口表仍在用内置型号推导（引擎已自报，但没接上）
- ⑤ 调度自动化（排队 / 并发上限 / 按能力选人）；批量操作；产出归档进知识库
- 历史遗留：`eng/onecode`（Web 版）**已休眠**，其 Phase 0 安全链条（`TERM_TOKEN` 默认空 + `0.0.0.0` 绑定 + `curl -k | bash`）**未修** —— 那是另一个产品，我判断为休眠就没动。**桌面版不是那个默认值**（见下）。

### D. 我**刻意不做**的（并说明理由）

| 不做的 | 理由 |
|---|---|
| 默认 `bypassPermissions` | 默认不提权已审计成不变量测试（5 条）。只有员工显式写 `bypass/yolo/full` 才提权 |
| ACP 客户端宣告 `fs` / `terminal` 能力 | 规范：未宣告即不支持 → Agent 不能经我们读写文件、起终端。**默认不给** |
| 权限请求默认放行 | 默认挑 `reject_once`；没有可拒绝的选项就回 `cancelled` |
| 把 ACP 挂进"打印模式"参数 | ACP 不吃 `-p`；按 `protocol` 分流，而不是假设所有引擎都长得像 `claude -p` |
| 用价格表估金额 | 金额一律**引擎自报**（含它自己的缓存/分档计价），我们不乘表、不估算 |
